Section 2: Thermal FEA and Adoption (14 pts)

Correct formulation/assembly/BCs (6), analytical verification and convergence (5), assumptions and learning explanation (3).

2.1 Governing Equation & Analytical Solution

Steady-state 1D heat conduction along a uniform cylindrical rod:

  -d/dx(kA dT/dx) = qA,   x ∈ [0, L]
  T(0) = T_left = 100°C,   T(L) = T_right = 20°C

Integrating analytically:

  T_exact(x) = T_left + (T_right - T_left)·x/L + [q/(2k)]·x·(L - x)

For the baseline parameters (L=1m, A=10⁻⁴m², k=10 W/(m·K), q=10000 W/m³), the peak temperature occurs at x=0.42m with T ≈ 188.2°C.

2.2 Element Formulation & Assembly (6 pts)

The rod is discretized into N linear two-node elements of length h = L/N. Implementation in src/core/fea.cpp:

Element stiffness matrix:

  K_e = (kA/h) * [[ 1, -1],
                   [-1,  1]]

Element load vector (uniform source):

  F_e = (qAh/2) * [1, 1]

Assembly: Direct stiffness method into a tridiagonal global system. Boundary conditions enforced via symmetric column reduction:

  F[1]   -= K[1, 0] · T_left
  F[N-1] -= K[N-1, N] · T_right

Solver: Thomas algorithm (tridiagonal matrix algorithm) — O(N) time complexity, O(N) space.

2.3 Analytical Verification & Convergence (5 pts)

Nodal Superconvergence

In 1D linear FEA with constant coefficients, the FE solution exhibits nodal superconvergence: nodal values match the exact solution to floating-point precision.

Midpoint Error & Convergence Order

Between nodes, the linear interpolation creates a secant line with predictable midpoint error:

  e_midpoint = q/(8k) · h² = 125 · h²

Convergence study results (from actual ctest execution):

2.4 Assumptions & Learning Explanation (3 pts)

  • Assumption 1: Uniform cross-section and constant material properties (k, q) along the rod. This enables closed-form analytical verification.
  • Assumption 2: Dirichlet-only boundary conditions (prescribed temperatures at both ends). Neumann (flux) BCs are not implemented.
  • Assumption 3: Steady-state analysis — no transient thermal capacitance term ρcₚ∂T/∂t.
  • Learning: The Thomas algorithm exploits tridiagonal sparsity for O(N) efficiency vs O(N³) for dense Gaussian elimination. Nodal superconvergence is a fundamental property of 1D Galerkin FEA with polynomial source terms — the proof follows from orthogonality of the error with respect to the finite element basis.

Section 3: Backpropagation (7 pts)

Correct handwritten chain rule and update (4); C++ gradient check and loss plot (3).

3.1 Network Topology

Single-sample MLP with input x=1.0, target y=2.0, initial weights w=0.5, b=0.0, v=1.0, c=0.0:

  z     = w·x + b       = 0.5
  h     = tanh(z)       ≈ 0.46211716
  y_hat = v·h + c       ≈ 0.46211716
  J     = ½(y_hat - y)² ≈ 1.18254182

3.2 Handwritten Chain Rule Derivation (4 pts)

Implemented in src/core/backprop.cpp and derived in docs/handwritten_backprop_notes.md:

  ∂J/∂c = (y_hat - y)                    = -1.53788284
  ∂J/∂v = (y_hat - y) · h                = -0.71068205
  ∂J/∂w = (y_hat - y) · v · (1-h²) · x   = -1.20946459
  ∂J/∂b = (y_hat - y) · v · (1-h²)       = -1.20946459

Simultaneous update (all gradients computed from original parameters, then applied):

  w₁ = w₀ - η·∂J/∂w = 0.5 - 0.1(-1.20946) = 0.62095
  b₁ = b₀ - η·∂J/∂b = 0.0 - 0.1(-1.20946) = 0.12095
  v₁ = v₀ - η·∂J/∂v = 1.0 - 0.1(-0.71068) = 1.07107
  c₁ = c₀ - η·∂J/∂c = 0.0 - 0.1(-1.53788) = 0.15379

6.2 Electrical & Interface Design (4 pts)

Full specification in docs/embedded_design.md (174 lines), including:

  • Power delivery network: 5 regulated voltage domains (+5V VBUS, +3.3V I/O, +1.8V FPGA VCCAUX, +1.2V MCU VCORE, +1.0V FPGA VCCINT)
  • JTAG pinout: 10-pin 1.27mm header (TCK, TMS, TDI, TDO, nTRST, VREF, GND) with bidirectional voltage level shifters (TXB0108)
  • JTAG daisy chain: MCU SWD TAP → FPGA boundary scan TAP → TDO return
  • Why JTAG is not a compute interface: IEEE 1149.1 is a single-bit serial shift register protocol lacking packet framing, flow control, and DMA. Throughput telemetry must use UART/USB or memory-mapped buses.

6.3 Working Mocks & Recovery (4 pts)

The EmbeddedManager class provides:

  • Device discovery: Lists all registered mock adapters with name, type, and capabilities.
  • Connect / Disconnect: State machine transitions (DISCONNECTED → CONNECTING → CONNECTED → DISCONNECTED).
  • Live telemetry: poll_telemetry() returns status metrics and numeric values (core temperature, ADC voltage, bus throughput).
  • Fault injection: trigger_failure("timeout") transitions to ERROR_TIMEOUT state with diagnostic message.
  • Auto-recovery: recover_device() pulses bus reset, flushes buffers, increments retry counter, and restores nominal CONNECTED state.

11.1 Prompt Strategy

Tasks were decomposed into priority-ordered, test-driven modules: FEA → Backprop → Multicore → Parsers → Embedded → Server/UI → Packaging. Each module followed a consistent prompt pattern:

  1. Define the mathematical formulation and interface contract
  2. Implement core logic with strict parameter validation
  3. Write comprehensive unit tests before integration
  4. Verify numerical accuracy against known analytical solutions

11.2 Iterative Refinement Examples

  • FEA convergence: Initial implementation was refined to evaluate midpoint errors (not just nodal errors) after recognizing that nodal superconvergence masks the true convergence order.
  • Backprop update semantics: Corrected from sequential to simultaneous parameter update — all gradients computed from original parameters before any weight is modified.
  • CTest working directory: Discovered that CTest defaults to the build directory, causing relative paths to data/ to fail. Added WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR} to all test targets.

11.3 Independent Verification

  • Every numerical claim was verified by actually running the compiled tests and inspecting output.
  • Convergence orders were verified against the theoretical value of exactly 2.000.
  • Gradient check errors were verified to be < 10⁻¹⁰ (far below the 10⁻⁵ tolerance).
  • Serial vs parallel equivalence was verified to machine precision.

Known Limitations (Honest Disclosure)

  1. No Windows .exe produced in this environment: Developed and tested on Ubuntu Linux x64. The dist/ contains Linux ELF binaries. Windows executables must be produced by running build_release.bat on a Windows 11 machine with Visual Studio installed. The CMakeLists.txt is fully configured for MSVC static /MT compilation.
  2. ASCII STL only: Binary STL parsing is not implemented. Files > 25 MB may cause JSON serialization overhead.
  3. CPU-based raycasting limit: Three.js CPU raycaster is responsive up to ~50,000 points. GPU picking or octree acceleration not implemented.
  4. Embedded interfaces are simulated: Real hardware drivers (OpenOCD, libftdi, Win32 COM ports) are abstracted behind C++ mock adapters. The simulated adapters demonstrate the correct state machine, error handling, and recovery patterns.
  5. Single-sample backpropagation: Network trained on one data point (x=1, y=2). Multi-sample batch training not implemented.
  6. No transient FEA: Only steady-state thermal analysis. Time-dependent analysis would require mass matrix assembly and time-stepping.
